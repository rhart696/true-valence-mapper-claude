# Privacy and data-handling requirements

Currency: authoritative · Owner: Richard Hart / ProActive ReSolutions · Created/reviewed: 2026-10-05
Related: See START-HERE and registry.

Names, descriptions and relationship interpretations can contain sensitive workplace information. Existing SQL's 'nothing to protect/public maps' comment is a historical assumption, not the intended client-data posture.

Inventory separately: browser localStorage; downloaded PDFs/PNGs; optional hosted sessions; hosting/request logs; database backups; optional research dataset; development-agent context. Verify provider region, access, processing arrangements and actual retention before disclosure. Determine applicable law by service/client/jurisdiction with appropriate advice; no legal-compliance claim is made here.

Pilot default: pseudonyms and minimum detail; local data unless verified sharing is explicitly chosen. Explain local device persistence, clear function, downloaded copy responsibility and shared-device risks. Research consent is separate, optional and specific; no implicit transmission to an AI interpreter or analytics service.

Cloud: distinguish visibility expiry, deletion job, backup retention and ability to revoke. Current source default of 30 days is not proof of physical deletion, especially with unrestricted inserts. No user deletion/revocation flow verified. Sharing must disclose capability access and recipient forwarding limits; don't call current design private until authorization is tested.

Finalize disclosure only after runtime verification. Test export/delete/expiry with synthetic records; capture proof without storing sensitive payloads. Pilot lead owns withdrawal/complaints and protocol retention settings; roles must be named before enrollment.
