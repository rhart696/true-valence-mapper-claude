# Pilot UX and accessibility specification

Currency: authoritative · Owner: Richard Hart / ProActive ReSolutions · Created/reviewed: 2026-10-05
Related: See START-HERE and registry.

Main flow: frame/context → map → executive noticing → optional selected inquiry → action/export. Support navigation without forcing completion of every field. Keep mapping conversation primary; structured fields open per relationship and facilitator prompts are optional/collapsible, not hidden scoring mechanisms.

Unconsidered data visibly differs from low. Inbound labels explicitly say inferred/believed perspective. Computed patterns receive descriptive provenance. Use text, arrow direction and existing dash cues in addition to color. Review representation at 8–12 and maximum 25 for legibility.

WCAG 2.2 AA target includes keyboard operation, visible focus, focus not obscured, accessible names, error messages, color contrast, target size where applicable, zoom/reflow and dialog focus management. Maintain a text/table alternative to the diagram. Assess applicable criteria individually; automated scans alone do not prove conformance.

Export: selectable inclusion of optional sensitive notes, direction legend, current-perception statement and date. PDF/image exports may need an accompanying accessible text report; PNG has no inherent semantic structure. Test export success and failure without incorrectly entering a success screen.

Privacy: before persistence/sharing, explain device/cloud location, recipients/capability access, expiry vs deletion and how to clear/revoke. Avoid claiming private sharing until server authorization is verified.
